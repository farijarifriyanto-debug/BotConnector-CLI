# packages/console rebrand report (OpenCode -> BotConnector)

## What packages/console actually contains

This is NOT just "a cloud billing/auth dashboard" — it is OpenCode's entire
live production SaaS stack for opencode.ai, split into six workspace packages:

- `app/` (`@opencode-ai/console-app`) — the full public marketing site
  (landing, Zen product page, Go product page, Black product page, download,
  enterprise, brand kit, changelog, benchmark pages, legal pages) PLUS the
  logged-in workspace/billing dashboard (API keys, members, usage, billing,
  referrals) PLUS the `zen/` API gateway itself (`/zen/v1/chat/completions`,
  `/zen/go/v1/*`, rate limiters, provider routing, pricing). Uses SolidStart,
  18 i18n locale files, Stripe billing UI, AWS SES email.
- `core/` (`@botconnector/console-core`) — shared business logic: billing,
  subscriptions ("Black"/"Go" plans), users, workspaces, Drizzle ORM schema
  and ~50 SQL migrations, AWS SES email sending.
- `function/` (`@botconnector/console-function`) — Cloudflare Worker functions:
  OAuth/auth issuer (GitHub + Google), auth redirect allowlist, log
  processing, stats.
- `mail/` (`@botconnector/console-mail`) — transactional email templates
  (currently just `InviteEmail.tsx`) built with `@jsx-email`.
- `resource/` (`@opencode-ai/console-resource`) — SST resource bindings
  (Cloudflare/Node config plumbing), no user-facing text.
- `support/` (`@opencode-ai/console-support`) — a small internal support-team
  lookup tool (account/workspace lookup by email/id/key), not customer-facing.

This is materially larger in scope than "a dashboard" — it's the real,
currently-live opencode.ai website + billing + LLM gateway, built by the
company Anomaly Innovations, Inc. I did not treat this as a blocker per the
task's own classification framework (BRANDING_VISIBLE / domain-flag /
Stripe-copy / legal-skip), which already anticipated exactly this shape of
content, but the volume is worth flagging explicitly.

## Changes made

All changes are literal text/copy substitutions (`OpenCode`->`BotConnector`,
lowercase `opencode`->`botconnector` where used as a brand/product reference
in display copy). No package names, env vars, routes, or URLs were touched.

## Flagged / intentionally skipped (with reasoning)

**Legal documents — `app/src/routes/legal/terms-of-service/index.tsx` and
`app/src/routes/legal/privacy-policy/index.tsx`** (~60 "OpenCode" references
combined): NOT edited. Line 38 of the ToS defines the actual legal party:
`<strong>ANOMALY INNOVATIONS, INC.</strong> ("OpenCode," "we" and "us")`.
This is a real, currently-binding legal contract naming a real corporate
entity. Bulk-replacing "OpenCode" with "BotConnector" throughout a live
Terms of Service / Privacy Policy without also changing (or being authorized
to invent) the legal entity, jurisdiction, and arbitration clauses would
produce a legally incoherent document, not a cosmetic rebrand. Treated this
the same as the task's "don't touch LICENSE files" instruction — flagging
for legal/product-owner review rather than editing.

**Live opencode.ai / anoma.ly infrastructure references** — left untouched
everywhere found, since these point at real, currently-functioning
endpoints that BotConnector does not own/control. Editing the display text
around them without changing the actual endpoint would be a half-migration
or would break the reference entirely:
- `app/src/config.ts` — `baseUrl: "https://opencode.ai"`,
  `github.repoUrl: "https://github.com/anomalyco/opencode"`,
  `social.twitter: "https://x.com/opencode"`, `social.discord: "https://discord.gg/opencode"`
  (drives the site's real GitHub/X/Discord nav links).
- `app/src/lib/changelog.ts` — the fetch URL
  `https://api.github.com/repos/anomalyco/opencode/releases` (real upstream
  repo the changelog is read from).
- `function/src/auth.ts` — `logo: "https://opencode.ai/favicon-v3.svg"`
  (live-hosted OAuth consent screen logo image).
- `core/src/user.ts` — `` `https://opencode.ai/email` `` (assetsUrl passed to
  the invite email template for image assets).
- `mail/emails/templates/InviteEmail.tsx` — `CONSOLE_URL = "https://opencode.ai/"`
  (builds the real "join workspace" link and default asset URL).
- `core/src/aws.ts` line 35 — `` FromEmailAddress: `OpenCode Zen <contact@anoma.ly>` ``.
  Left entirely untouched: this is the verified AWS SES "From" address tied
  to the real `anoma.ly` sending domain (SPF/DKIM/DMARC configured on that
  domain). The domain can't be swapped without new SES domain verification,
  and changing only the display name while keeping `anoma.ly` would produce
  a confusing/mismatched sender identity. Flagging as an infra/deployment
  decision, per the task's auth-domain guidance.
- `app/public/robots.txt` — `Sitemap: https://opencode.ai/sitemap.xml` (x2).
- Also implicitly: `function/src/auth-redirect.test.ts` was left entirely
  untouched — it's a unit test asserting real allowed OAuth redirect
  domains (`opencode.ai`, `dev.opencode.ai`) against `isAllowedAuthorizationRedirect`;
  not branding text, and touching it risks obscuring what the auth
  allowlist logic actually protects.

**Brand-kit page — `app/src/routes/brand/index.tsx`**: not edited. Every
string in this file (import paths, download button filenames like
`"opencode-logo-light.svg"`) refers to the *actual* logo/wordmark asset
files under `app/src/asset/brand/`. Since those asset files themselves were
not (and per the task, should not be) redesigned, renaming the filename
strings here would make the brand-kit page claim to serve
"botconnector-logo-light.svg" while actually downloading the untouched
OpenCode artwork — worse than leaving it consistent. Left as-is pending the
actual asset redesign.

**Logo SVG asset — `app/src/asset/logo-ornate-{dark,light}.svg`** (the pair
named explicitly in the task, referenced by the root README): inspected
directly. Confirmed these are **pure path-traced pixel-art wordmarks** —
each file is a `<svg>` containing only `<path>` elements with hand-placed
coordinates forming the letterforms of "opencode" (no `<text>` element
anywhere; `grep -o "<text[^>]*>"` returned zero matches). This is visual
logo art, the same category as the TUI's ASCII splash logo elsewhere in this
rebrand effort — flagging for separate design work rather than attempting a
text-substitution edit that doesn't apply here. The same is true of every
other wordmark/logo SVG under `app/src/asset/` and `app/src/asset/brand/`
and `app/src/asset/lander/` (e.g. `zen-ornate-*.svg`, `go-ornate-*.svg`,
`opencode-wordmark-*.svg`) — none were edited.

**Dead/unreachable testimonial — `app/src/routes/enterprise/index.tsx` line 97**
("Thanks to OpenCode, we found a way...") is inside `<Show when={false}>` and
never renders to users. Left as-is since it's not currently visible;
noting it in case it's ever re-enabled.

**`.opencode/agent/css.md`**: an internal dev-tooling agent config file
(instructions for an AI coding agent on how to write CSS for this project).
Contains no product branding text; the `.opencode/` directory name itself is
a technical tooling convention (this repo's own agent config folder), out of
scope for a branding-visible/packaging-identity change.

**Package names / workspace identifiers**: left untouched throughout, per
existing repo-wide policy — `@opencode-ai/console-app`, `-core`, `-function`,
`-mail`, `-resource`, `-support`; no `description` fields exist in any of
the six `package.json` files, so there was nothing to change there anyway.

**No LICENSE-type file found** in `packages/console/` (checked; only
`"license": "MIT"` fields in package.json, which are metadata, not a
LICENSE file body — left untouched, same policy as elsewhere).

## Concerns for the product owner / follow-up work

1. **Terms of Service / Privacy Policy** still say "OpenCode" and name
   "ANOMALY INNOVATIONS, INC." as the operating legal entity throughout.
   These need real legal review (new entity? new DBA? dual-branding
   disclosure?) before any text in them changes — this is a legal decision,
   not a code-text decision.
2. **Live domain footprint**: `opencode.ai`, `anoma.ly` (SES), and
   `github.com/anomalyco/opencode` are hardcoded in `config.ts`,
   `changelog.ts`, `auth.ts`, `user.ts`, `InviteEmail.tsx`, and
   `robots.txt`. If/when BotConnector stands up its own domain, auth
   endpoint, SES sending domain, and GitHub org, these all need a
   coordinated infra + code cutover (not a text find/replace) — auth,
   outbound email deliverability, and the changelog feed all depend on
   them functioning today.
3. **Logo/wordmark artwork** (`logo-ornate-*.svg` plus the full
   `asset/brand/` and `asset/lander/` sets) is still the real OpenCode
   pixel-art wordmark. The `/brand` page actively distributes these as
   "OpenCode brand assets" to visitors — needs new BotConnector artwork
   before this page (or the root README's embedded logos) reflects the new
   brand.
4. The real `@OpenCode` X/Twitter handle is quoted in 5 places (4 in
   `zen/index.tsx`, 1 key x18 locales) as testimonial attribution — if/when
   BotConnector wants its own testimonials, this is content/marketing work,
   not a text-substitution task.

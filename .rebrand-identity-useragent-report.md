### Skipped / flagged as ambiguous (not changed)

1. **`packages/opencode/src/plugin/openai/codex.ts:561`** — `output.headers.originator = "opencode"`. This is OpenAI's Codex-specific `originator` header (distinct from `User-Agent`, set right next to the UA line I did fix). It's paired with a specific registered OAuth `CLIENT_ID` (`app_EMoamEEZ73f0CkXaXp7hrann`) for this app's Codex integration. Unlike a generic User-Agent (which providers generally don't validate), `originator` fields on some provider APIs are validated server-side against the registered client's expected value. Changing it risks silently breaking the ChatGPT Pro/Plus OAuth flow. Left untouched and flagged for the product owner / someone who can verify against OpenAI's actual validation behavior.
2. **`packages/opencode/src/plugin/xai.ts:115`** — `referrer: "opencode"` in the xAI OAuth device-authorization POST body, alongside the same file's registered `CLIENT_ID` (`b1a00492-073a-47ea-816f-4c329264a828`). Same reasoning as above — this is an OAuth form field tied to a specific registered client, not a plain HTTP User-Agent header, and may be validated server-side by xAI. Left untouched; `packages/opencode/test/plugin/xai.test.ts:442` (`expect(parsed.get("referrer")).toBe("opencode")`) correspondingly left untouched too, since it's still testing accurate behavior.
3. **`infra/monitoring.ts:45,91,136,268`** and **`infra/stats.ts:44`** — these reference a `user_agent` *column* in what looks like an analytics/monitoring query filter (`{ column: "user_agent", op: "contains", value: "opencode" }`), i.e. they're querying historical/live traffic logs for User-Agent strings that already went out under the old "opencode" identity. Not a site that *constructs* an outgoing UA string — changing the filter value would silently stop matching real historical opencode-branded traffic and wouldn't match anything until new botconnector-branded traffic exists. Left untouched as out of scope (infra dashboards/monitoring, not the running product's outgoing identity) and flagged in case the product owner wants a *separate*, deliberate decision about when to switch the monitoring filter.
4. **`packages/app/...`**, **`packages/core/src/github-copilot/copilot-provider.ts:66`** (`ai-sdk/openai-compatible/${VERSION}` via `withUserAgentSuffix`) — these use `navigator.userAgent` (browser API, unrelated) or an ai-sdk-internal UA suffix with no "opencode" literal in it. Not applicable, no change needed.
5. **`opencode/${type}${id}-${timestamp}` git-branch-naming patterns** in `github/index.ts:720`, `packages/opencode/src/cli/cmd/github.handler.ts:1088,1090`, `packages/opencode/src/worktree/index.ts:183` (and their tests) — these construct git branch name prefixes, not User-Agent/identity strings sent to a provider.

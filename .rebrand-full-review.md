## Issues

### Critical (Must Fix)

### Important (Should Fix)
1. **`packages/botconnector/script/postinstall.mjs` was not updated and is now broken by the binary
   rename** — not caught in either the CLI/TUI or the console/web reports' flagged-items lists
   (they flagged `Dockerfile` and `script/publish.ts` but missed this file). It computes
   `base = \`opencode-${platform}-${arch}\`` and `sourceBinary = "opencode.exe"/"opencode"` to
   locate and npm-install the per-platform prebuilt-binary optional-dependency packages, then copies
   their `bin/opencode(.exe)` to `targetBinary = path.join(__dirname, "bin", "opencode.exe")`. Since
   `build.ts` (already renamed on this branch) now publishes those platform packages under
   `botconnector-${platform}-${arch}` names with `bin/botconnector`, this script — the actual npm
   postinstall path end users hit when installing the CLI via npm — will fail to resolve the binary
   package and fall through to its final `throw new Error("...right opencode CLI package...")`. This
   is a real, deploy-breaking gap in the same category the CLI/TUI report already flagged for
   `Dockerfile`/`publish.ts`, just missed. Needs the same fix (or an explicit decision) before this
   branch ships a working npm-installed CLI.
2. **`packages/botconnector/Dockerfile`** (already flagged by the CLI/TUI report, independently
   reconfirmed here): `COPY dist/opencode-linux-*/bin/opencode /usr/local/bin/opencode`,
   `RUN opencode --version`, `ENTRYPOINT ["opencode"]` — all reference paths/binaries that no longer
   exist post-rename. Confirmed still present and unfixed; correctly flagged as needing an external
   identity decision (registry/org) before fixing, per the report.
